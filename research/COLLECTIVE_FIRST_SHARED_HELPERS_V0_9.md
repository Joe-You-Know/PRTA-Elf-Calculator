# PRTA v0.9 — collective-first shared-helper planning (November 19, 2026)

**Reproducible artifact:** conversation attachment `prta_collective_first_helpers_v0_9.zip` (Python source, inherited v0.8 no-good/occurrence tools, six new tests, full benchmark audit, README). Executable source is in ZIP; this GitHub record is the persistent research checkpoint.

## Change from v0.8

Before choosing any individual target recipe, gather every unsatisfied target's exact candidate arithmetic producers. Propose helper H when at least two *distinct* target obligations have an executable candidate producer consuming H; score the group by goal coverage and an explicitly heuristic one-step construction cost. Enumerate one/two shared-helper group options before resolving the entire dependency graph. Forced producer choices must be recursively constructed; all source values need actual instructions and all completed programs are independently replayed using original positive-integer, exact-division, register, and target requirements.

Matched target-by-target control gets the same original and invented arithmetic candidate graph and the same recursive closure/allocator, but no forced collective helper. The full evaluated portfolio comes from externally credited public 141,086-instruction CSV, not original authorship by this project.

## Verified controls

Starts 2,3; targets 8,12. Four-step reference uses 6,8,9,12. Collective planner invents 4=2+2, then 8=2×4 and 12=3×4: **3 steps**. The no-forced-helper control retains four. Six unit tests pass; especially undefined helper cannot be used as an arithmetic value; mandatory target coverage remains; physical rejection callback retains legal baseline.

## Completed full scored audit, conservative bound

1000/1000 programs independently valid in both modes. Up to 4 ranked seed helpers, one forced helper per candidate family, max 5 family attempts/puzzle, recursive beam 3. Fresh candidate proposals 31,530 (not necessarily executed). Target-by-target: 1,000 proposals and final 141,086 instructions. Collective: 4,960 proposals; 3,193 failed to complete a source-valid dependency closure, 1,763 not shorter, 4 arithmetic/allocator rejections. **No scored improvement; final 141,086**. Both output hashes equal the public baseline `21d1d5245de5d41810e06ce6435df99059b2ba8a35f2bfcde3256e827675a5d7`. Combined single-run time 20.511s (not a speedup claim). An attempted wider 80-family search timed out; it is not an additional completed result.

## Precise epistemic boundary

Choice is made collectively *before* output program construction, but the helper scoring uses direct target coverage rather than exhaustive multi-depth marginal network benefit. Forced seed closure often fails because the helper's producer dependencies are inaccessible or cyclical under the bounded beam. Physical v0.8 conflict ledger and source occurrence receipt tools are bundled; v0.9 provides a source-preserving physical acceptance hook, but **no shorter scored candidate reached it**, so geometry/conditional exclusion does not explain any score savings. An unselected helper is not a witnessed literal absence or zero. No Kaggle submission warranted.
