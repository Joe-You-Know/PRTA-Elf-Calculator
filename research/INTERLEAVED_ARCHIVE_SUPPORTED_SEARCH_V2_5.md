# PRTA Elf v2.5 — interleaved archive-supported arithmetic / physical synthesis (2026-11-19)

**Status:** executable completed, 158/158 regressions pass, independent event replay and 1,000-puzzle matched guarded-versus-archive audit. Complete current-conversation executable ZIP `prta_elf_interleaved_archive_search_v2_5.zip` and `README_V25.md`.

## What changed

v2.3 invented complete numerical candidate graphs first and then scheduled triangular physical contacts; v2.4 supplied archive-supported future consumer semantics but not a fully interleaved numerical invention search. v2.5 has one bounded forward state per partially built construction: it retains exact source occurrence identities, numerical target witnesses, actual source/receiver triangular faces, live contacts, immutable discharged receipts, original event timeline, explicit consumer duties, and virtual register occupancy. For each numerical candidate (+, positive -, *, exact /) it also chooses a physical receiving face. Before consuming any constructed source J in a proposed new join K, it declares a separate duty for each of J's original A/B contacts and each exact future operand role at K. If both roles reference J, four source-specific duties are created; no duplicate numerical source is fabricated. These remain **pending during the arithmetic join**, then close only on independent exact original source ID and operand-role event witness. Under the archive policy source contact relays discharge early, while the source and its archived history remain available for future use. Guarded comparison keeps the earlier route occupied until the dependent join has been witnessed.

The event-derived future-boundary is used to check candidates for exact duplicate boundaries (zero merged in completed runs), not a scalar value-set key. The separate 48-register last-read allocator compiles complete histories, and a distinct interpreter validates all source/target, positive/exact division and arithmetic bounds. The physical machine is the finite *authored* triangular shared-edge grammar, not a universal PRTA theorem. The future consumer ledger is incrementally committed as a **next-step joining decision**; unchosen potential future obligations remain unspecified. No complete open-future-law derivation is claimed.

## Forced counterexample

Start 2 at face 2, 3 at face 4, radius 3 hop cap 4. Join j0: 2+2=4 on face 0. In archive mode, its two original contacts discharge and archive. Declare two future-use duties (j0,A,j1,left) and (j0,B,j1,left), preserving pending status, then perform real j1: j0 + 3=7 on face 9 and complete the duties only after its actual verified occurrence. Four receipts archived; independent event replay and Elf program `[['+',0,0,2],['+',2,1,0]]` pass. Under guarded policy, j1 on face 9 fails with occupied old relay. This is a concrete finite-grammar reachability difference.

Additional self-discovered exact physical controls: start (2,3), targets (5,6) in 2 instructions, (4,7,9) in 3, and (8,12) in 3. Numerical constructors can differ from intended hand examples but are independently checked.

## Open issues

- No automatic rigid rotation, multi-face contact transport or source release in interleaved proposal generation; underlying v2.4 machine supports them.
- Equal-numerical-value suppression remains a search heuristic; cannot assume it is a sound source-equivalence rule.
- All future consumer obligations are *not* derived from an unknown, still-unbuilt future graph. Current obligations arise only when choosing each next arithmetic event.
- Weak collective multi-target helper ranking and very shallow competition budgets prevent evidence of score reduction.
- Virtual physical register slots are separate from independently valid last-read Elf allocator. Need physical resource lifetime integration for deeper construction.
