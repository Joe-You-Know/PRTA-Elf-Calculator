## User goal and actual implementation

Integrate lawful forward joins into v1.6 **event-derived** future boundaries and emit real legal Elf Calculator programs. Each initial input is a distinct occurrence with authored actual triangular face assignment and register. Every proposed arithmetic event must satisfy exact positive arithmetic and two simultaneous actual shared-edge contact paths, and receives its own source occurrence identity, face and register. A whole sequence of such joins is produced forward. Deduplication uses `future_boundary`, which retains source terms and IDs, physical placements, contact receipts, epochs, register and lifetime states, plus witnessed withholding. Only successful genuine joins become `[op,i,j,dst]` instructions, independently interpreted using all exact-positive-division and target-witness rules. Candidate event histories are independently replayed from their initial placement before emission. The compiler can also explicitly append turning and witnessed optional nonobservation events to a candidate history without attributing numeric consequences to them; the underlying event interpreter supports transport and release, but the **scored forward search does not automatically propose those alternative actions**.

**Constructive control:** source (2,3), targets (5,6), initial face placement (1,8) in radius-three patch, synthesizes `5=2+3` and `6=2×3`. Emits two actual legal register instructions `['+',0,1,2]`, `['*',0,1,3]`, with four exact edge-contact receipts, source-owned event replay and independent arithmetic validation. Explicit withheld-observation + join still compiles to one actual join instruction, never a free value. 62/62 unit tests pass (52 inherited, 10 new).

A larger physical run exceeded execution timeout and is excluded.

**Critical limits:** Declared strict full-edge contact rule is one experimental PRTA grammar, not all algebraic joins. It currently excludes two uses of the *same* source occurrence (as two independent receiving ports), even though `2+2` is arithmetically legal. Alternate initial placements and automatic rotations/transports/withholding not yet searched. Same-value candidate occurrences skipped as a heuristic, not safe future equivalence. Fresh dedicated register per event up to puzzle cap (usually 48), no lifetime-based reuse. Event boundary comparison is overly conservative and produced **zero** merges; no measured speed advantage from future equivalence. Failure to find a route within patch/hop/face budget is unresolved, not physical nonexistence. The full 1,000-puzzle result does **not** beat the reference score, and no Kaggle submission is justified.

**Next:** allow lawful repeated-source contact obligations without creating a new numeric source; search alternative source placements, discrete turns, relay path transports and authorized withholding as history actions; add register lifetime reuse, derive alpha-canonical future boundary congruence under physical contacts, and run stronger equal-candidate ablations. Avoid equating literal absence, constructive-zero report, unobserved source and numeric zero. Source evidence in downloadable code/test/audit bundle.
